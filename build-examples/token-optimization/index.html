What is a Token?

In Large Language Models (LLMs), a token is the fundamental unit of text processing. Instead of reading text character by character or word by word, models break text down into chunks called tokens. These chunks can be as short as a single character or as long as a whole word.

For example, the word "unbelievable" is typically broken down into 3 tokens: "un", "believ", and "able". Common words often correspond to a single token, while rare words or complex symbols are split into multiple.

Note: Tokenization is model-specific. OpenAI models (GPT), Anthropic models (Claude), and Google models (Gemini) all use slightly different tokenizers.

Why Optimize?

Reduce Cost

API providers charge per token. Reducing your prompt size directly lowers your monthly bill and improves your project's ROI.

Lower Latency

Fewer tokens mean faster processing. Shorter prompts lead to quicker "Time to First Token" responses and a snappier user experience.

Context Limits

Every model has a maximum context window. Efficiency lets you fit more relevant data into every request and reduces the risk of cutting off important info.

Core Optimization Techniques

1. Prompt Compression

Minimize verbose instructions. Remove filler words, use imperative voice, and eliminate redundant instructions. Modern LLMs are highly capable and don't need "polite" phrasing or long preambles to understand your intent. Direct, clear instructions often perform better and use significantly fewer tokens than conversational ones.

# Verbose:
"Please try to rewrite this following paragraph to be much shorter while making sure you keep all the important information."

# Optimized:
"Summarize this paragraph concisely, retaining all key points."

2. System Prompt Reuse & Caching

Cache static instructions. Keep your instructions separate from user data. Many providers now offer prompt caching for frequently reused system messages, which can save up to 90% on input costs for long prefixes. By structuring your application to reuse a stable system prompt, you can dramatically improve both speed and cost-effectiveness.

# Set a static system prompt:
"Role: Expert Editor. Tone: Professional. Task: Fix grammar and flow."

3. Structured Output

Use JSON for machine consumption. Request JSON or specific formats instead of free-form prose to reduce "chatty" responses and make downstream consumption easier. Explicitly asking for a structured format prevents the model from adding unnecessary conversational filler. This approach ensures you only pay for the data you actually need for your application's logic.

# Prompt:
"Analyze the sentiment. Respond ONLY with a JSON object: {\"sentiment\": \"...\", \"score\": 0.0}"

4. Conversation Truncation

Manage history strategically. Don't send the entire chat history. Summarize older messages or only send the last N messages to stay within limits and keep the model focused on the current task. As conversations grow, the "noise" from early messages can confuse the model and inflate costs. Implementing a sliding window or summarization layer is essential for long-running agents.

# Strategy:
# - Keep system prompt
# - Keep most recent 5 messages
# - Summarize previous 10 messages into one

5. Model Routing

Select the right tool for the job. Use cheaper, faster models (like Claude Haiku or GPT-4o-mini) for simple tasks like classification or routing before calling larger models. Not every request requires the reasoning power of a flagship model. Intelligent routing allows you to balance performance and price by matching task complexity to model capability.

if (isSimpleTask(input)) {
  return callHaiku(input);
} else {
  return callOpus(input);
}

6. RAG & Intelligent Chunking

Retrieve only what is necessary. Instead of dumping whole documents into context, use Retrieval-Augmented Generation to only include the most relevant text snippets. High-quality chunking and embedding-based search ensure that the model has exactly the context it needs and nothing more. This technique is the most effective way to handle massive knowledge bases within narrow context windows.

# Approach:
# 1. Embed document segments
# 2. Query vector DB for top 3 matches
# 3. Insert ONLY those matches into prompt

7. Few-Shot Example Pruning

Quality over quantity. Include only the most diverse and high-leverage examples. Five perfect, distinct examples are often better than twenty mediocre or repetitive ones. Over-providing examples can lead to "recency bias" or dilute the model's focus. Carefully curated few-shot examples provide the best "bang for your buck" in terms of performance per token.

# Bad: 10 similar examples
# Good: 3 distinct edge cases

8. Output Length Control

Set boundaries on verbosity. Use parameters like max_tokens and explicit brevity instructions to prevent the model from being overly verbose. Models are often trained to be helpful and descriptive, which can lead to long-winded answers you didn't ask for. Controlling the output length directly manages your generation costs and keeps responses focused.

{
  "max_tokens": 100,
  "prompt": "Explain RAG in one sentence."
}

Frequently Asked Questions

Does whitespace count towards tokens?

Yes. Spaces, tabs, and newlines all count as tokens or parts of tokens. In some tokenizers, multiple spaces might be combined, but generally, any character you send contributes to the total count.

Do all models tokenize the same way?

No. Each model family usually has its own tokenizer (e.g., tiktoken for OpenAI, Llama's tokenizer, etc.). While the "4 characters per token" rule is a good rule of thumb for English, it varies by language and model.

Is fewer tokens always better?

Not necessarily. If you compress a prompt too much (making it "lossy"), the model might lose the context it needs to perform well. The goal is "maximum efficiency," not just "minimum tokens."

Do system prompts and user prompts both count?

Yes. The total tokens in a request include the system prompt, all messages in the conversation history, the user's latest prompt, and any specialized tokens used for formatting (like "Im_start" or "Im_end").

What is Prompt Caching?

Prompt caching allows API providers to store frequently used prefixes (like long system instructions or many-shot examples) so you don't have to pay full price for them on every single request, often reducing costs by 90% for those specific tokens.
